# UNIVERSAL MARKET SIGNALS BOARD — MINIMAL PRODUCT SPEC

## 1. Purpose

Market Signals Board is a filtering, classification, and comparison layer for scraped job data.

It helps users turn a large mixed job database into a clear market map for a chosen research direction.

The feature should answer:

```text
Which jobs are relevant?
What are buyers asking for?
Which requests repeat?
Which buyer types appear often?
Which skills/tools are demanded?
Where are budget and urgency signals?
Which market patterns look strongest?
```

---

## 2. Core Output

The feature should produce reusable market knowledge:

```text
filtered relevant jobs
classified job signals
buyer/request/need data
repeated pattern groups
skill and tool demand
budget and urgency signals
ranked market signals
```

---

## 3. Core Flow

```text
Existing scraped jobs
→ create board
→ define board goal
→ define market query
→ filter relevant jobs
→ classify filtered jobs
→ extract comparison fields
→ group repeated patterns
→ calculate scores
→ review market map
```

---

## 4. Board Creation

User creates a board with:


## 5. Board Goal

Board Goal defines how results should be interpreted.

Allowed examples:

```text

Skill demand research
Niche comparison
Service idea validation
Buyer segment research
Job market analysis
Offer research
```

The same job can have different value depending on the board goal.

## 10. Relevance Rules

### Relevant

Use when:

```text
job clearly matches the board query
job matches multiple include keywords
job has relevant skills/tools
job belongs to the target market
```

### Maybe Relevant

Use when:

```text
job partially matches the query
context is unclear
job belongs to an adjacent market
```

### Irrelevant

Use when:

```text
job matches exclude keywords
job clearly belongs to another category
job has no meaningful relation to the board query
```

## 13. Scoring Logic

The score should stay simple and explainable.

Inputs:

```text
relevanceScore
budgetStrength
clientStrength
urgencyStrength
problemClarity
skillMatch
difficulty
speedToValue
repeatability
```

Formula:

```text
marketSignalScore = average(
  relevanceScore,
  budgetStrength,
  clientStrength,
  urgencyStrength,
  problemClarity,
  skillMatch,
  speedToValue,
  repeatability,
  difficultyAdjusted
)
```

The score is interpreted through the Board Goal.

---

## 14. Score Meaning

### Score 5

```text
clear match
clear buyer/request
strong budget/client signal
strong need
high repeatability
strong skill/tool signal
easy to compare
high value for board goal
```

### Score 4

```text
good match
clear request
some budget/client signal
useful for pattern detection
```

### Score 3

```text
valid signal
some unclear fields
still useful for comparison
```

### Score 2

```text
weak signal
unclear request
low usefulness for current board goal
```

### Score 1

```text
barely useful
low relevance
low comparison value
```

## 17. Pattern Strength

```text
Weak
Medium

```

Rules:

```text
Strong = 5+ jobs and average score >= 4
Medium = 3+ jobs and average score >= 3
Weak = fewer jobs or unclear signal
```

Use:

```text

```

Do not invent missing data.

### Keep Original Language


## 28. Done When

```text
User can create a Market Signals Board for any market query.

User can filter a mixed job database into relevant, maybe relevant, and irrelevant jobs.

User can compare relevant jobs by category, client type, problem, buyer need, budget, urgency, skills, difficulty, speed to value, and score.

User can see repeated patterns without reading every job manually.

User can manually correct wrong classifications.

User can understand which market patterns are strongest in the selected job collection.
```
